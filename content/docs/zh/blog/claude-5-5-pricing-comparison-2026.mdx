## Opus 5.5 值不值 Sonnet 5.5 两倍的价钱？

这是唯一需要真正做决定的问题，而 2 倍这个比值让它变成算术题而不是感觉题。

以「一次 Sonnet 调用」为 1 个单位 S：

- **全程用 Opus**：每个请求 2S
- **路由**：每个请求 1S；比例 *p* 的请求校验失败要升级，升级成本是 S（白跑的尝试）+ 2S（Opus 重试）= 3S

令两者相等：`1 + 3p = 2`，得 **p = 1/3**。

| 升级率 | 全程 Opus | 路由（先 Sonnet） | 谁更省 |
|---|---:|---:|---|
| 10% | 2.00S | 1.30S | 路由，省 35% |
| 20% | 2.00S | 1.60S | 路由，省 20% |
| **33%** | 2.00S | 2.00S | 打平 |
| 50% | 2.00S | 2.50S | Opus，省 20% |
| 80% | 2.00S | 3.40S | Opus，省 41% |

> **关键结论**：因为 Opus 5.5 恰好是 Sonnet 5.5 的两倍价，只要需要升级的请求低于三分之一，先跑 Sonnet、失败再升级就比直接用 Opus 便宜。

这张表藏了两个坑，别忽略：

1. **升级不只有 token 成本，还有延迟成本。** 失败的请求要跑两轮往返。交互式对话里用户能感觉到，批处理任务里感觉不到。
2. **升级需要可判定的校验器。** 你不能靠「模型好像没把握」来路由，得有确定性检查 —— JSON schema 校验、跑测试、diff 能不能干净应用、数值断言。没有校验器，「33% 阈值」本身就没法测量。

没有校验器的时候，更省事的做法是选定一个模型然后别再优化：吞吐优先选 Sonnet 5.5，正确性优先选 Opus 5.5。

## Claude 5.5 支持 Anthropic 原生 Messages 接口吗？

支持，这点值得单独确认，因为它决定了迁移是「改个 URL」还是「重写客户端」。

平台上每个 Claude 模型都同时标注 `anthropic` 与 `openai` 两种接口类型，也就是同一个 Key、同一个余额可以走两种请求格式：

**Anthropic Messages 格式** —— `POST /v1/messages`，必须带 `anthropic-version` 头：

```bash
TOKENPAPA_API_KEY="sk-..."

curl https://api.tokenpapa.ai/v1/messages \
  --oauth2-bearer "$TOKENPAPA_API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-5-5",
    "max_tokens": 1024,
    "messages": [
      {"role": "user", "content": "把这份迁移方案总结成 5 条要点：..."}
    ]
  }'
```

**OpenAI 兼容格式** —— `POST /v1/chat/completions`，不需要额外头：

```python
from openai import OpenAI

client = OpenAI(
    api_key="sk-...",
    base_url="https://api.tokenpapa.ai/v1",
)

resp = client.chat.completions.create(
    model="claude-sonnet-5-5",       # 或 "claude-opus-5-5"
    messages=[{"role": "user", "content": "审查这个 diff 有没有竞态条件：..."}],
    max_tokens=1500,
)

print(resp.choices[0].message.content)
print(resp.usage)                    # 输入/输出 token 数，用来算钱
```

两条路走的是同一批模型、同一个价格。实用规则：**你现在的 SDK 说什么格式就用什么格式**。用 Anthropic SDK 就走 `/v1/messages`，用 OpenAI SDK 就走 `/v1/chat/completions`。为了省钱换格式没有意义 —— 两种格式之间没有价差。

> **关键结论**：TokenPAPA 上 11 个 Claude 模型全部支持 Anthropic 原生 Messages 接口和 OpenAI 兼容接口，迁移时不需要换客户端库，只需要换 base URL 和模型名。

## 有一个数字需要你自己再确认

`claude-haiku-5-5` 标价是 **输入 $0.01 / 输出 $0.50** 每百万 token。这是 50:1 的输出输入比 —— 平台上其他 Claude 模型都在 5:1 或 10:1；同时它的缓存输入价等于输入价（完全没有缓存折扣）。

这两点都比较反常，所以不建议在没核对实时页面的情况下按它规划量级。这个费率是平台今天发布的数字，便宜档位本身合理 —— 但 50:1 在任何成本模型里的行为和 5:1 完全不同，一旦标价调整，按它做的预算就会直接失效。给负载定规模之前，先去 [https://tokenpapa.ai/pricing](https://tokenpapa.ai/pricing) 确认。用法上建议只接短输出任务，这种情况下哪怕输入价差 10 倍也只是几分钱的事。

## 这份价格表不能告诉你的事

说清楚，因为「哪个更便宜」单独问是错的：

- **token 单价不等于「解决一个任务」的成本。** 需要两次尝试的模型，单价减半也不便宜。要按「成功产出」计价，不是按调用计价。
- **本文不含 Sonnet 5.5 与 Opus 5.5 的质量差异。** 我核的是价格，不是跑分。别把 2 倍价格读成 2 倍能力。
- **推理 token 按输出计价。** 如果这类模型产生内部推理，它落在输出计数里，按 5 倍于输入的费率计费。预算要看 `usage.total_tokens`，不是看答案长度。
- **缓存价假设命中。** 写缓存和未命中是不同计费。46.6% 是 80% 命中率场景，不是承诺。
- **托管 API，不能自部署。** 合规场景的数据处理影响照常适用，见 [隐私政策](https://tokenpapa.ai/privacy-policy)。

只有当 **超过三分之一的请求确实需要升级** 时才值得。常态走 Sonnet 记 1 个单位，升级一次记 3 个单位（失败的尝试 + Opus 调用），全程 Opus 记 2 个单位。升级率低于 33% 时路由更省 —— 前提是你有确定性的校验器能判定「失败」。

### Claude 5.5 支持 Anthropic Messages 原生格式吗？

**支持。** 每个 Claude 模型都同时标注 `anthropic` 与 `openai` 两种接口类型。带 `anthropic-version` 头调 `POST /v1/messages`，或走 OpenAI 兼容的 chat completions —— 同一个 Key、同一个价格、没有格式差价。

### Claude Haiku 5.5 是什么价？

**输入 $0.01 / 输出 $0.50** 每百万 token（2026-11-11 标价），50:1 输出比且无缓存折扣。按它规划负载前请先去定价页确认当前费率。

### 换个 Key 才能用 Claude 5.5 吗？

**不需要。** 所有 Claude 模型都在 `default`、`Starter`、`Pro`、`Enterprise` 分组里，你现有的 Key、base URL、余额都能直接用，只改 `model` 字符串。
