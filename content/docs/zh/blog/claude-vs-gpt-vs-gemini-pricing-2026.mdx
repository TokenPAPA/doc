## 为什么账单由输出 token 说了算？

因为输出单价是输入的 5 倍，而大多数负载的实际输出占比比想象的高 —— 一旦把推理 token 与多步智能体的往返都算进去。

在 4:1 的输入输出比下，输出只占 token 数量的 20%，却占账单的 **62.5%**。如果换成 1:1 的翻译或摘要负载，输出占账单 83.3%。

| 输入:输出 | 输出占 token 数 | 输出占账单（5 倍倍率） |
|---|:---:|:---:|
| 10:1（带引用的 RAG） | 9.1% | 35.7% |
| 4:1（聊天） | 20.0% | 62.5% |
| 1:1（翻译） | 50.0% | 83.3% |
| 1:3（短提示长生成） | 75.0% | 93.8% |

这就是为什么输入单价极低的模型也可能输。Sonnet 5.5 的输入比 Haiku 5.5 贵 186 倍，但输出只贵 19 倍；对 10:1 的 RAG 负载，两者真实差距是 5.6 倍而不是 186 倍。

由此直接推出三条控制手段：

1. **每次调用都设 `max_tokens`。** 不受限的生成就是不受限的账单，而成本正好落在高倍率的那一侧。
2. **限制智能体循环步数。** 每一步都会把累积上下文作为输入重发，同时再付一次输出；十步不是一步的十倍，输入侧是平方级增长。
3. **先测真实比例再选型。** 团队常假设 10:1，上线后实测 3:1，月账单直接翻倍。

## 什么流量该走哪家？

决定分流的不是单价，而是失败率。两款旗舰同价的情况下，正确的框架是按任务难度分层，而不是按厂商站队。

| 流量类型 | 最优性价比选择 | 理由 |
|---|---|---|
| 分类、打标、意图路由 | `claude-haiku-5-5`（$0.01 / $0.50） | 任务已饱和，旗舰的溢价买不到提升 |
| 高频摘要、抽取 | `gemini-3.8-flash`（$0.62 / $3.10） | 输出密集但输出单价低 |
| 长上下文 RAG 问答 | `gemini-4-argon` 或 `deepseek-v4-pro` | 输入便宜且输出倍率低 |
| 通用聊天、工具调用、产品默认档 | `claude-sonnet-5-5` 或 `gpt-6.1-sol` | 同价，用自己的评测集定 |
| 硬核智能体编程、跨文件重构 | `claude-opus-5-5`（$3.72 / $18.60） | 2 倍价，升级率超过 33% 才划算 |
| 前沿研究、长周期自主任务 | `gpt-6-astra` 或 `claude-fable-5-1` | 5–9 倍价，只留给别的模型确实做不动的活 |

Opus 这笔账值得单独算。正常走 Sonnet 5.5 是 1 个单位；升级一次是 3 个单位（失败的 Sonnet 尝试 + Opus 那次调用）；全程用 Opus 是 2 个单位。所以升级率低于 33% 时路由划算，高于 33% 时就亏。如果你的升级率是 45%，实际成本是 1 + 0.45 × 2 = 1.9 个单位 —— 只比全程 Opus 略微便宜，再把多出来的延迟和编排代码算进去，其实就是白忙。

## 怎么在不改代码的情况下切换三家？

一个 Key、一个 base URL、一个 `model` 字符串。三家都能走 TokenPAPA 的 OpenAI 兼容接口，同一份客户端代码可以访问上表每一行。

```python
from openai import OpenAI

client = OpenAI(
    api_key="sk-your-tokenpapa-key",
    base_url="https://tokenpapa.ai/v1",
)

MODEL = "claude-sonnet-5-5"  # 换成 gpt-6.1-sol 或 gemini-4-argon 即可

resp = client.chat.completions.create(
    model=MODEL,
    messages=[
        {"role": "system", "content": "你是一名资深代码审查员。"},
        {"role": "user", "content": "审查这段 diff 有没有竞态：\n" + diff},
    ],
    max_tokens=800,   # 一定要设；输出单价是输入的 5 倍
)
print(resp.choices[0].message.content)
```

```python
CANDIDATES = ["claude-sonnet-5-5", "gpt-6.1-sol", "gemini-4-argon"]

```

跑之前有两个厂商差异必须先知道：

- **推理系模型不接受 `max_tokens`。** `gpt-6.1-sol` 与 `gpt-6-astra` 要求用 `max_completion_tokens`，并且拒绝非默认的 `temperature`。在 Sonnet 5.5 上能跑的请求，在 Sol 上可能因为这两点直接返回 HTTP 400。
- **Claude 两种格式都认。** `claude-sonnet-5-5` 同时列出 `anthropic` 与 `openai` 两种接口类型，想用原生语义可以调 `POST https://tokenpapa.ai/v1/messages` 并带 `anthropic-version` 头，也可以留在 OpenAI 兼容路由上，Key 不变。

如果你是从 Anthropic 或 OpenAI 官方账号迁移过来，改动只有两行 —— Key 和 base URL，业务代码不用动。

## 常见问题

### 2026 年 Claude 比 GPT 便宜吗？

不便宜也不贵：两款当前旗舰定价完全相同。`claude-sonnet-5-5` 与 `gpt-6.1-sol` 都是每百万输入 1.86 美元、每百万输出 9.30 美元、每百万缓存命中 0.10 美元，在成本轴上没有任何一方占优，只能靠输出质量与接口契约来选。

### Gemini 是三家里面最便宜的吗？

绝对价格最低，但不在同一档位。`gemini-4-argon` 每百万输入 1.64 美元、输出 8.20 美元，比 Sonnet 5.5 低 11.8%，平台把它定位为面向高频简单任务的轻量模型。真正的低价档是 `gemini-3.8-flash`，0.62 与 3.10 美元。

### 为什么账单总比按 token 算出来的高？

因为三家当前旗舰的输出单价都是输入单价的 5 倍。在常见的 4:1 输入输出比下，输出只占 token 数量的 20%，却占了账单的 62.5%。所有估算都必须把输出按 5 倍加权，并且每次调用都要设 `max_tokens`。

### 提示缓存会改变哪家更便宜的结论吗？

不会。缓存只能把账单压小，不会改变排序。缓存命中价在 Sonnet 5.5 与 `gpt-6.1-sol` 上都是每百万 0.10 美元，仅相当于输入价的 5.4%，三家的折扣比例几乎一样，所以相对排序不变。

### 生产环境的聊天机器人该用哪家？

从 `claude-sonnet-5-5` 或 `gpt-6.1-sol` 起步（同价，挑自己评测集里赢的那个），把分类与抽取流量分流到 `claude-haiku-5-5` 或 `gemini-3.8-flash`。这个分层能砍掉「全旗舰」账单的 60–90%，而简单流量上的回答质量不受影响。
