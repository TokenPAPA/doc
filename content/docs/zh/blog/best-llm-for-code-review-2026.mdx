## 为什么代码审查打破了常规的选型逻辑

**1. 输入量是输出的二十倍以上。** 一次审查要发送 diff、每个被改动文件的全文、评审规则和 PR 描述，输出只是一份简短的发现列表。4 万输入 token 对 1500 输出 token，输入价格占了约 95% 的成本——赢家是输入便宜、输出克制的模型，而不是聊天排行榜上的头名。

**2. 长上下文是刚需。** 一个改了八个文件的 diff，逐个文件审没有意义——审查者必须看到被改函数在别处怎么被调用。128K 是底线，重构类改动要 256K（`kimi-k3`）或 1M（`gpt-5.6-luna`）。

**3. 输出 token 才是贵的那个。** 多数平台输出单价是输入的 3-10 倍。一个每次审查都要"想"3000 token 的模型，比只输出 800 token 的模型贵得多。显式设置 `max_tokens`、要求输出有界的发现列表，是整条流程里最省钱的优化。

> **关键结论**：代码审查里输入价格说了算，输出纪律决定剩下的部分。按 TokenPAPA 费率，DeepSeek V4 Flash 的输入价（$0.14/1M）比 GPT-5.6 Sol（$13.50/1M）**便宜 96%**，而审查正是输入密集型负载，这个差距几乎原封不动地体现在月账单上。

## 哪些模型是真的"审查得好"？

| 能力 | 检查点 | 达标模型 |
|---|---|---|
| 读完整份改动 | 窗口能否容纳 diff + 相关文件 | 128K 是实际底线；重构用 `kimi-k3`(256K)、`gpt-5.6-luna`(1M) |
| Agentic 编程能力 | 看代码基准而非聊天榜 | DeepSeek V4 Flash 在 Terminal Bench 2.1 得 **82.7**，高于贵 50 倍的模型 |
| 结构化输出 | 能否稳定输出可发布的 JSON | `qwen3.7-plus`、`deepseek-v4-pro` 更守 schema |
| 代码专用变体 | 是否为代码专门训练 | `gpt-5.3-codex`、`kimi-k2.7-code`、`doubao-seed-2-0-code-preview` |

一条实用法则：**每个 diff 都用一个便宜审查者，重要 diff 再加一个强审查者**。按 diff 本身路由（改动文件数、行数、是否命中 `auth/`、`crypto/`、`migrations/`），而不是按作者资历路由。这样约 90% 的审查停留在 $0.006 这一档，剩下 10% 真正有风险的才交给贵 2-20 倍的模型。

## 一个模型，还是两段式流水线？

**第一段——分流（每个 PR）**：`mimo-v2.5` 或 `deepseek-v4-flash` 只回答一个问题：这个 diff 需不需要细审？纯文档、纯格式化改动到此为止。

**第二段——审查（通过分流的 PR）**：日常改动用 `deepseek-v4-flash`；命中认证、支付、迁移、并发的改动升级到 `deepseek-v4-pro` 或 `claude-sonnet-4`。

**第三段——汇总（可选）**：两个模型结论不一致时，再用一次便宜调用把发现合并成一份评论列表，避免重复刷屏。

因为每一段共用同一个 `base_url` 和同一个 API Key，"再加一个模型"的成本是一行字符串，而不是一次新集成。

## 快速开始：一次调用完成代码审查

```python
from openai import OpenAI

client = OpenAI(
    api_key="your-tokenpapa-key",
    base_url="https://tokenpapa.ai/v1"
)

RUBRIC = """审查这份 diff，只输出具体问题的 JSON 列表：
[{"file": "...", "line": 0, "severity": "high|medium|low", "issue": "...", "fix": "..."}]
忽略风格偏好，只报正确性、错误处理与安全问题。"""

diff = open("changes.diff").read()

response = client.chat.completions.create(
    model="deepseek-v4-flash",     # 可换成 qwen3.7-plus / kimi-k3 / claude-sonnet-4
    messages=[
        {"role": "system", "content": RUBRIC},
        {"role": "user", "content": diff},
    ],
    max_tokens=1500,               # 限制昂贵的输出 token
)

print(response.choices[0].message.content)
```

两个细节最关键：评审规则**每次调用保持不变**（输出更稳定，重复前缀还能吃到服务端缓存折扣）；`max_tokens` **显式设置**（输出单价是输入的 3-10 倍）。把规则放 system、diff 放 user，这段脚本就是一个 CI 步骤或 pre-commit hook。

## FAQ

### 2026 年代码审查用哪个大模型最好？

按 TokenPAPA 费率，**DeepSeek V4 Flash** 是最佳默认值：**输入 $0.14 / 1M**、**输出 $0.42 / 1M**。代码审查是输入密集型任务，一次约 4 万输入 token、2000 以内输出的审查成本约 **0.6 美分**。只有涉及安全或架构的改动才升级到 DeepSeek V4 Pro 或 Claude Sonnet 4。

### 便宜模型做代码审查靠谱吗？

对大多数审查场景靠谱。关键是模型能否正确读懂 diff 并给出具体、可执行的评论，而 `deepseek-v4-flash`、`qwen3.7-plus` 这类低价模型完全胜任。DeepSeek V4 Flash 在 Terminal Bench 2.1 上得分 **82.7**，便宜不等于弱。

### 用大模型审查一次 pull request 要花多少钱？

假设 4 万输入 token + 1500 输出 token：**DeepSeek V4 Flash 约 0.6 美分**、Qwen 3.7 约 0.9 美分、GPT-5.6 Luna 约 1.5 美分、**Claude Sonnet 4 约 14 美分**。按每月 500 次 PR 计算，DeepSeek V4 Flash 约 **3 美元**，Claude Sonnet 4 约 **71 美元**。

### 不改现有 CI 工具能接上自动化代码审查吗？

能。代码审查本质就是一次 chat completion 调用，任何能发 HTTPS 请求的 CI runner 或 pre-commit hook 都可以调用 `https://tokenpapa.ai/v1` 这个 OpenAI 兼容端点。从 DeepSeek 换到 Qwen、Claude 或 Kimi 只是**改一行 `model` 字符串**——不需要新 SDK，也不需要每个供应商一个 Key。
