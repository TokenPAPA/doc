# Claude 5.5 Pricing: Sonnet 5.5 vs Opus 5.5 vs Haiku 5.5

**Claude Sonnet 5.5 costs $1.86 per 1M input tokens and $9.30 per 1M output tokens. Claude Opus 5.5 costs $3.72 and $18.60 — exactly twice Sonnet on both sides. Both are live on TokenPAPA, both accept the Anthropic Messages format, and both are cheaper than the models they replace.**

That last part is the unusual bit. New flagship generations usually cost more than the ones they displace. This one went the other way: Sonnet 5.5 is **41.9% cheaper** than Sonnet 4.6, and Opus 5.5 is **30.3% cheaper** than Opus 4.6, on identical ratios in both directions. Nothing in the API changed to earn that discount — same endpoints, same request shape, same key.

This article is the pricing reference for that generation: every Claude ID on the platform, the per-task arithmetic, the break-even math for choosing between Sonnet and Opus, and the two request formats you can use.

## Is Opus 5.5 worth exactly 2× Sonnet 5.5?

This is the only selection question that matters, and the 2× ratio makes it arithmetic rather than intuition.

Model the two strategies in units of "one Sonnet call" (S):

- **Always Opus**: every request costs 2S.
- **Route**: every request costs 1S. A fraction *p* of requests fail validation and escalate, and an escalated request costs S (the failed attempt) + 2S (the Opus retry) = 3S.

Setting the two equal: `1 + 3p = 2`, so **p = 1/3**.

| Escalation rate | Always Opus | Route (Sonnet first) | Winner |
|---|---:|---:|---|
| 10% | 2.00S | 1.30S | Route, 35% cheaper |
| 20% | 2.00S | 1.60S | Route, 20% cheaper |
| **33%** | 2.00S | 2.00S | Tie |
| 50% | 2.00S | 2.50S | Opus, 20% cheaper |
| 80% | 2.00S | 3.40S | Opus, 41% cheaper |

> **Key insight**: Because Opus 5.5 is exactly 2× Sonnet 5.5, routing to Sonnet first and escalating on failure is cheaper than always using Opus as long as fewer than one in three requests needs the escalation.

Two things that table hides, and you should not ignore them:

1. **Escalation has a latency cost, not just a token cost.** A routed request that fails then retries pays two round trips. For interactive chat that is user-visible. For batch jobs it is invisible.
2. **Retry-on-failure requires a validator.** You cannot route on "the model seemed unsure". You need a deterministic check — a schema validation, a test suite, a diff that applies cleanly, a numeric assertion. If you do not have one, you are measuring vibes, and the 33% threshold is not measurable either.

Where a validator does not exist, the cheaper move is usually to pick one model and stop optimizing. Pick Sonnet 5.5 for throughput, Opus 5.5 for correctness-critical work, and move on.

## Do the 5.5 models speak the Anthropic Messages API?

Yes, and this is worth checking explicitly because it is the difference between a drop-in migration and a rewrite.

Every Claude ID on the platform lists **both** `anthropic` and `openai` endpoint types. That means two request formats against the same key and the same balance:

**Anthropic Messages format** — `POST /v1/messages`, requires an `anthropic-version` header:

```bash
TOKENPAPA_API_KEY="sk-..."

curl https://api.tokenpapa.ai/v1/messages \
  --oauth2-bearer "$TOKENPAPA_API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-5-5",
    "max_tokens": 1024,
    "messages": [
      {"role": "user", "content": "Summarise this migration plan in 5 bullets: ..."}
    ]
  }'
```

**OpenAI-compatible format** — `POST /v1/chat/completions`, no extra headers:

```python
from openai import OpenAI

client = OpenAI(
    api_key="sk-...",
    base_url="https://api.tokenpapa.ai/v1",
)

resp = client.chat.completions.create(
    model="claude-sonnet-5-5",       # or "claude-opus-5-5"
    messages=[{"role": "user", "content": "Review this diff for race conditions: ..."}],
    max_tokens=1500,
)

print(resp.choices[0].message.content)
print(resp.usage)                    # input/output token counts for cost tracking
```

Both routes hit the same models at the same prices. The practical rule: keep whatever format your SDK already speaks. If you are on the Anthropic SDK, use `/v1/messages`; if you are on the OpenAI SDK, use `/v1/chat/completions`. Switching formats to save money does not work — there is no price difference between them.

> **Key insight**: All 11 Claude model IDs on TokenPAPA support the native Anthropic Messages endpoint and the OpenAI-compatible endpoint under one key, so migrating from a direct Anthropic account does not require changing your client library — only your base URL and model string.

## What does prompt caching change?

Cached input is where Claude pricing gets materially cheaper, and the 5.5 generation kept the discount while cutting the base rate.

| `claude-sonnet-4-6` | $0.32 | 10% of input price |
| `claude-opus-4-6` | $0.534 | 10% of input price |

Rerunning the PR-review workload with **80% of input served from cache**:

| Model | No cache | 80% cached | Saving |
|---|---:|---:|---:|
| `claude-sonnet-5-5` | $1,088/mo | ~$581/mo | 46.6% |
| `claude-opus-5-5` | $2,176/mo | ~$1,162/mo | 46.6% |
| `claude-sonnet-4-6` | $1,872/mo | ~$1,043/mo | 44.3% |
| `claude-opus-4-6` | $3,124/mo | ~$1,740/mo | 44.3% |

Two caveats that decide whether you actually see these numbers:

- **Caching only pays on a stable prefix.** A system prompt in the same position, a fixed document corpus, an unchanged repository preamble. If your prompt is rebuilt differently each call, the cache never hits and the 46.6% is fiction.
- **Maximise the cached share, not the model choice.** At 80% cache hit rate, `claude-sonnet-4-6` ($1,043/mo) lands close to uncached `claude-sonnet-5-5` ($1,088/mo). Two levers that look like one decision.

## What this pricing does not tell you

Being explicit, because "which is cheaper" is the wrong question on its own:

- **Token price is not cost per solved task.** A model that needs two attempts is not cheaper at half the rate. Measure cost per *successful* outcome, not per call.
- **Quality differences between Sonnet 5.5 and Opus 5.5 are not in this article.** I have verified prices, not benchmark scores. Do not read the 2× ratio as a 2× capability claim.
- **Reasoning tokens are billed as output.** If these models emit internal reasoning, it lands in your output count at the output rate — five times the input rate. Budget on `usage.total_tokens`, not on the visible answer length.
- **Cached pricing assumes a cache hit.** Cache writes and misses are billed differently. The 46.6% figure is an 80%-hit-rate scenario, not a guarantee.
- **Hosted API, not self-hosting.** Standard data-handling implications apply for regulated workloads; see the [privacy policy](https://tokenpapa.ai/privacy-policy).
