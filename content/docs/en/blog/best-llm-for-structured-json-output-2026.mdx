## Why JSON output breaks the usual "best model" ranking

Most model comparisons are written for chat. Structured output has three properties that change the ranking.

**1. Schema adherence is a skill, not a side effect.** A model can write beautiful prose and still invent field names, drop required keys, or wrap valid JSON in markdown fences. What you need is the probability that one call returns parseable, schema-correct JSON. That is closer to a coding ability than a chat ability, which is why coding-tuned models (like `kimi-k2.7-code`, `gpt-5.3-codex` or `qwen3.7-plus`) frequently outperform prose-specialists on this task.

**2. Output tokens are the expensive tokens.** An extraction call sends a prompt and a document (input) and gets back a JSON object (output). Because output is priced 3-10x higher, a model with a slightly higher input rate but a much lower output rate can be cheaper per completed extraction.

**3. Retries are invisible line items.** If 2% of calls return invalid JSON and you retry them on a stronger model, the effective cost of the stronger model includes the retry layer. A cheap model with a 98% valid rate often beats a strong model with a 99.5% rate by 5-20x on total cost — this is the argument for the two-tier pipeline below.

> **Key insight**: for structured JSON output, input price dominates bulk cost, schema adherence dominates reliability, and retries dominate the surprise on your invoice. On TokenPAPA rates, DeepSeek V4 Flash input is **96% cheaper than GPT-5.6 Sol** ($0.14 vs $13.50 per 1M) — and because extraction is an input-heavy workload, that gap lands almost unmodified in your monthly bill.

## How do you force valid JSON from any model on one API key?

You do not need a separate "JSON endpoint". OpenAI-compatible APIs support `response_format: {"type": "json_object"}` as a parameter, and every model on TokenPAPA accepts it through the same `base_url`. Two details decide success: the schema lives in the prompt, and `max_tokens` is set explicitly — a truncated JSON object is invalid JSON.

```python
from openai import OpenAI

client = OpenAI(
    api_key="your-tokenpapa-key",
    base_url="https://tokenpapa.ai/v1"
)

SCHEMA = """Extract a customer record as JSON with exactly these fields:
{"company": string, "contact_email": string, "plan": "free"|"pro"|"enterprise",
 "annual_revenue_usd": number, "signup_date": "YYYY-MM-DD"}
Return ONLY the JSON object. Do not wrap it in markdown."""

response = client.chat.completions.create(
    model="qwen3.7-plus",              # swap to deepseek-v4-flash or gpt-5.6-luna
    messages=[
        {"role": "system", "content": SCHEMA},
        {"role": "user", "content": email_text},
    ],
    response_format={"type": "json_object"},
    max_tokens=400,                    # bound the expensive output tokens
)

import json
record = json.loads(response.choices[0].message.content)
```

The same call shape works for `deepseek-v4-flash` as the budget extractor and for `gpt-5.6-luna` when the document is long or the schema is nested. If you want the OpenAI-style declared-schema path rather than prompt-only, set `response_format={"type": "json_schema", "json_schema": {...}}` with the model string in the table — the platform passes it through unchanged, exactly as described in the [OpenAI compatibility guide](https://doc.tokenpapa.ai/en/docs/blog/openai-compatibility-guide).

Two habits eliminate most invalid-JSON failures. First, stabilize the prompt: keep the schema string constant across calls so provider-side caching discounts the repeated prefix — the same trick that drives costs down in agent loops (see [Which LLM API is cheapest for AI agents in 2026](https://doc.tokenpapa.ai/en/docs/blog/cheap-llm-api-for-ai-agents)). Second, wrap every call in a validate-and-retry loop: parse with `json.loads`, and on failure resend once with the validator's error message appended.

## Should you use one JSON model or a two-tier pipeline?

Single-model extraction is fine until the bill or the failure rate annoys you. A two-tier pipeline fixes both with no new infrastructure:

**Tier 1 — bulk extraction (every document).** `deepseek-v4-flash` does the high-volume work at ~$0.41 per 1K calls. Because the schema string is stable and input-heavy, automatic context caching cuts the repeated prompt cost further — DeepSeek's caching discounts repeat input tokens by roughly 90%, covered in [DeepSeek cache hit optimization](https://doc.tokenpapa.ai/en/docs/blog/deepseek-cache-hit-optimization).

**Tier 2 — repair and high-stakes passes.** When the validator rejects a record, or when the document is a legal contract rather than an invoice, escalate the single retry to `qwen3.7-plus` (schema fidelity) or `gpt-5.6-luna` (long context and structured outputs). Escalation is one `model=` string — the same "third call reconciles a disagreement" pattern used in multi-stage review pipelines ([Which LLM is best for code review in 2026](https://doc.tokenpapa.ai/en/docs/blog/best-llm-for-code-review-2026)).

Because every tier shares a key and a base URL, the pipeline is just a dict of model strings, not a set of vendor integrations.
